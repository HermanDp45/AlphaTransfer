# 07 — Lean Canvas: «факт о выгодном моменте для перевода»

## Основание

Это артефакт узла **Lean Canvas** исходного n8n-пайплайна, построенный для H1 из [06_rice_prioritization.md](06_rice_prioritization.md). Canvas описывает гипотезу продукта, а не доказанную бизнес-модель: в исходных материалах нет исследований пользователей, тарифов, внутренних воронок или unit-экономики.

| Блок | Содержание |
|---|---|
| **1. Проблема** | 1) Клиент видит текущий курс, но не понимает, насколько он хорош относительно недавней истории. 2) Выбор дня перевода приходится делать самостоятельно, следя за рынком или принимая случайный момент. 3) Пуш может быть ошибочным/устаревшим и быстро исчерпать доверие к каналу. |
| **2. Существующие альтернативы** | Перевести сразу; вручную следить за курсом; сравнить курс в других приложениях (это сравнение спредов, не времени); отложить перевод без понятного критерия; использовать общий курс-виджет/новости. |
| **3. Решение** | Сигнальный слой выбирает редкие моменты, прошедшие walk-forward проверку. Пуш сообщает один проверяемый факт о прошлом/настоящем: «сейчас курс выгоднее, чем в X % дней за последние 3 месяца». Переход ведёт на перевод; при изменении условий — на прозрачное состояние с актуальной суммой. Cooldown: не более 1–2 пушей в неделю. |
| **4. Уникальное ценностное предложение** | «Помогаем выбрать момент для перевода семье по понятному факту о курсе — без необходимости следить за рынком и без обещаний, куда курс пойдёт дальше». |
| **5. High-level concept** | «Курс-радар для регулярного перевода семье»: не трейдинг-сигнал, а редкое и объяснимое напоминание в уже используемом банковском приложении. |
| **6. Нечестное преимущество** | Гипотеза, а не подтверждённый актив: сочетание контекста регулярного перевода в банке, доверенного канала и накопленной калибровки объяснимых сигналов по коридорам. Его нельзя считать преимуществом до проверки качества сигналов и законных ограничений на использование продуктового контекста. |
| **7. Сегменты клиентов** | Первичный: физлица, регулярно переводящие рубли близким в TJS, UZS, KGS, AMD или KZT. Вторичный для последующих тестов: эпизодические отправители и разные коридоры — только после подтверждения эффекта у регулярных отправителей. Пользователь — отправитель; бенефициар — получатель перевода. |
| **8. Ранние последователи** | Повторно переводили в один и тот же коридор; имеют включённые сервисные пуши; открывают приложение и завершают переводы самостоятельно; не находятся в неподходящем/ночном окне доставки. Это критерии eligibility для теста, не профиль реальных людей. |
| **9. Ключевые метрики** | **Offline:** lift и hit rate сигнала на out-of-time walk-forward, выгода момента в bps, частота 1–2 пуша/нед., кучность. **Pilot:** incremental transfer conversion 24h против холдаута; incremental net volume; конверсия push → экран → подтверждение. **Guardrails:** opt-out, жалобы, отмены, пушей на клиента, каннибализация объёма следующих 7/28 дней, корректность текстов/сумм. |
| **10. Каналы** | Основной — сервисный push в мобильном приложении, отправляемый по сигналу в разрешённое локальное время. Product surfaces: deep link на экран международного перевода, при необходимости in-app карточка. Не предполагается платный acquisition-канал: цель — проверить ценность для существующего пользователя переводов. |
| **11. Структура затрат** | Получение/нормализация открытых курсов; разработка и расчёт сигналов; A/B-инфраструктура и пуш-доставка (за рамками хакатона — как допущение пилота); дизайн и разработка экрана; аналитика/контрольный холдаут; комплаенс-проверка текстов; поддержка и мониторинг качества. |
| **12. Доход/экономический эффект** | Не отдельная плата за функцию. Предполагаемый эффект — дополнительная валовая маржа от **инкрементального** объёма трансграничных переводов и потенциальное удержание доли кошелька. Формула из кейса: число действительно сдвинутых коммуникацией переводов × средний чек × маржа. До пилота нельзя подставлять значения или заявлять окупаемость. |

## Самый ранний проверяемый сценарий

1. Сигнал H1 проходит заранее зафиксированный offline-порог качества на конкретном коридоре, включает cooldown и разрешённое время отправки.
2. Eligible-клиенты этого коридора случайно делятся на treatment и holdout.
3. Treatment получает фактический пуш; holdout — нет. Обе группы сохраняют доступ к обычному переводу.
4. Через заранее выбранное окно сравниваются инкрементальная конверсия, net-объём и guardrails.
5. Если эффект не подтверждён или ухудшаются guardrails, гипотеза отклоняется/переформулируется; рост кликов сам по себе не является основанием масштабировать решение.
