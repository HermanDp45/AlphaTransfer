# Продуктовый контракт двух модельных сценариев

Текущий `final_solution/alphatransfer_final/product.py` использует NOW-модель и честно маркирует `offline_target=NOW`. Его factual-copy labels (`OBSERVED_RISE`, `HISTORICAL_LOW_REFERENCE` и т.д.) описывают текстовый факт, а не отдельную обученную CLOSING-модель. Этот legacy контракт не изменён.

Новый исследовательский профиль сохраняет два **не взаимоисключающих** утверждения:

| Поле | NOW — основной сигнал | CLOSING — дополнительное подтверждение |
|---|---|---|
| Модельный вопрос | Не появится ли более выгодный курс на всём горизонте? | Будет ли курс дороже в конце горизонта? |
| Ориентация | R = RUB за единицу валюты получателя; меньше лучше | Та же ориентация |
| Hit label | R[t] ≤ min(R[t+1]…R[t+5]) | R[t+5] > R[t] |
| Probability | Собственная NOW-голова | Собственная CLOSING-голова |
| Знаменатель метрики | Все исходные NOW-контакты | Только subset с дополнительным CLOSING tag |
| Общая частота | Каждый контакт считается один раз | Дополнительный tag не создаёт второго контакта |

Например, путь 100→99→101→102→103→105 подтверждает CLOSING, но не NOW. Плоский путь подтверждает NOW, но не строгое CLOSING. Поэтому вероятность и hit этих событий нельзя подменять друг другом. На реальных данных события могут одновременно подтвердиться; их теги не обязаны делить уведомления на непересекающиеся группы.

**Default research profile — `dual_annotations`.** Применяется уже выбранная NOW-policy; дата и основной NOW-текстовый смысл сохраняются. CLOSING-аннотация появляется только при одновременном прохождении собственного прошлого порога и наблюдаемом росте `ret1>0`. Её score берётся из CLOSING checkpoint, а не переименовывается из NOW. Никакой дополнительной отправки и добора частоты. Это post-readout исследовательский профиль; результатов 2026 недостаточно для перспективного доказательства, а отрицательные результаты 2025 delay сохраняются.

Варианты `relative_quality` и `now_confirmed_closing` доступны только как явные диагностики. Первый может вытеснять NOW более слабым CLOSING, второй эксклюзивно переименовывает выбранный тип и тем самым меняет условный NOW-знаменатель. Их нельзя выдавать за неизменное качество всего NOW-потока.

## API и причины решения

`resolve_scenarios(candidates, as_of, context=None, state=None)` — self-contained stdlib API. Каждый кандидат несёт scenario, точный target contract, probability, свой fitted threshold, past-validation baseline rate, model cutoff, calibration end и past/current factual context. Неизвестные outcome-поля (`target`, `forward_bps`, `future_min` и т.п.), будущие timestamps и противоречащие друг другу факты закрывают соответствующий путь.

Результат содержит `selected` с основным NOW-сигналом и список `annotations` с отдельным CLOSING-сигналом, его probability и target contract. `next_state` возвращается копией, без мутации исходного состояния и без реальной отправки. `research_only=true`, `authorized_contact=false`.

Общий клиентский cap применяется поверх рыночных кандидатов: максимум два контакта за последние семь календарных дней, включая другие маркетинговые контакты, дедупликация дня и дополнительный календарный cooldown. Это более строгий CRM-слой, чем диагностическая рыночная частота по календарным неделям/CBR-сессиям. Backtest cadence не объявляется гарантией фактической частоты после клиентских ограничений.

`context.require_strong_fact=true` включает дополнительное требование наблюдаемого снижения/низкого ранга для NOW и роста для CLOSING. По умолчанию такого принудительного низкого ранга для обученной NOW-метки нет: допустим нейтральный факт текущего опубликованного курса. Отдельные sensitivity таблицы показывают цену более сильного текстового гейта.

## UI и текст

В исследовательской карточке допустима явная маркировка «Модельный сигнал: выгодно сейчас», а для secondary tag — «Есть модельные признаки закрытия окна». Это название оценки модели, не гарантированный исход. В фактическом теле сообщения — только известный курс, его наблюдаемое изменение либо ранг по прошлой истории. Вероятность будущего события не превращается в утверждение «курс вырастет» или «лучшего курса не будет».

При открытии приложения показывается актуальная исполнимая котировка правильной стороны и сумма получателю. Историческая CBR reference-цена и Halyk BANK SELL-признак не подменяют этот quote. Внутренний forecast score, сценарный tag и текстовый факт хранятся отдельными полями.

## Предложение интеграции

Добавить optional `scenario_profile=dual_annotations` после проверки root. Существующая NOW-policy определяет основной market event. Отдельный CLOSING scorer возвращает свой контракт и вероятность на том же date/corridor; adapter добавляет annotation без изменения NOW signal ID/даты. Сохранять в audit log обе версии модели, оба порога, обе вероятности, factual evidence, known-at и причину отсутствия annotation. Оценивать NOW и CLOSING раздельно; выводить общий cadence и utility лишь там, где определение действительно общее. До согласования root `final_solution` не изменяется.
