# Предобъявленный протокол: устойчивость KZT Halyk к задержке данных

Протокол записан до вычисления результатов continuation. Старые V3/V4 данные, код и результаты доступны только для чтения. Никаких новых внешних источников или рыночных исходов не вводится.

1. Одна задача: KZT, h5, Brier на всех тех же рыночных датах; дополнительно качество/частота candidates с прежним cooldown и previous-validation threshold. Model family и tree settings наследуются без поиска из V4.
2. Набор фиксирован: V3 long global calibration; V3 long KZT-only calibration; Halyk lag1; retrain Halyk lag2 reference; deterministic date-hash lag augmentation (L1/L2, одна строка на market-date/corridor); dropout всех Halyk features на 25% training dates; равновесное ensemble двух моделей lag1/lag2; minimax prior-validation shrink calibrated Halyk lag1 к calibrated long V3, alpha∈{0,.25,.5,.75,1}.
3. Normal deployment и delayed deployment различаются **только Halyk feature availability после cutoff**. Lag1-trained модель принимает L1 либо L2; lag2-trained — L2 либо L3; lag ensemble — (L1,L2) либо (L2,L3). Ни retraining, ни новой калибровки после появления test labels. CBR/CNY base features не задерживаются этим stress test.
4. Pooled HGB и 40 KZT Newton stumps — V4 settings. Для augmentation/dropout stage-2 shrink grid минимизирует worst prior-validation raw Brier по L1/L2. Для lag1/lag2 сохраняется первоначальная нормальная calibration view. Robust calibrators обучаются на двух равновесных validation views одних дат; это не новые независимые observations.
5. Primary selection rule: среди фиксированных robust методов минимальный max(normal Brier, delayed Brier) на development 2023–2025. Отдельный строгий критерий «без потери качества»: normal Brier не хуже текущего Halyk lag1, delayed Brier не хуже V3 long. Если ни один метод не проходит, пишем это прямо. Никаких границ tolerance, выбранных после результатов.
6. Выбор семейства закрывается до новых вычислений 2026. 2023–2025 и прежний 2026 ранее просматривались: это retrospective robustness development, не новый независимый holdout.
7. January scheme: cutoff2026-01-01, train10y до2025, отдельная calibration2025; train и calibration labels должны созреть строго до следующей границы. Никаких labels2026 в fit.
8. March scheme: cutoff2026-03-01, rolling12month calibration [2025-03-01,2026-03-01), train10y до2025-03-01. Matured January/February2026 labels разрешены только здесь. Основное сравнение January/March — одинаковые даты **с2026-03-05**, плюс отдельные все доступные даты начиная с соответствующего cutoff. Не выдумываем данные до конца сентября: frozen CBR input заканчивается2026-09-01, зрелые h5 outcomes раньше.
9. Evaluator явно строит calibration history [cutoff−12m,cutoff) и carry cooldown. `core.run_fold` не вызывается: его January-only history не подходит к March cutoff. Delay stress начинается на cutoff, initial cooldown state берётся из нормальной прошлой истории; test outcomes в selection не входят.
10. Отдельные реально переобученные V3 baselines для каждого cutoff. Annual baseline probability/threshold/candidate parity против старых артефактов; saved checkpoints и SHA; manual prediction recomputation; label maturity; future-input poison до cutoff; zero-tree/base identity; cutoff-history and policy-prefix tests.
11. Уверенность оценивается по реальным calendar blocks, не по duplicated lag views. Relative gains не интерпретируются как causal client uplift или executable bank P&L. Вся работа на одном CPU thread.
