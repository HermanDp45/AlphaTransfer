# Открытые рыночные данные и банковские котировки

Фактически загружены и использованы в обучении три разных вида данных.

- **KASE:** дневные цены сделок, VWAP, объём и число сделок RUB/KZT, USD/KZT, CNY/KZT за 2020–2026. API `trade-results/currency-spot?date_trade=...` найден в публичном коде официального сайта. Весь календарь запрашивается явно: в Казахстане бывают рабочие выходные. Пустой ответ сохраняется, возврат другой даты отклоняется. Дублирующие сессии не суммируются: сначала выбирается полная запись с ценой, объёмом и числом сделок, затем по `num_sess` — последняя среди одинаково полных. Решения для всех 224 групп сохранены в `kase_session_resolution.csv`. Дневные bid/offer часто пересекаются; в модели они **не используются как spread**. [Официальная страница торгов](https://kase.kz/en/markets/foreign-currencies), [расписание и результаты](https://kase.kz/en/app-gateway/currency/).
- **Halyk:** реальная история банковского курса **продажи** RUB, USD и EUR физическим/юридическим лицам. Сайт прямо объясняет направление графика. Это независимый банковский индикатор, но RUB→KZT отправитель продаёт банку RUB: нужная ему историческая сторона buy отсутствует. Поэтому не считаем полученные bps клиентской экономией. [Описание графика](https://halykbank.kz/en/exchange-rates).
- **MOEX:** доступные в исходных данных число сделок, диапазон CNY/RUB и разность ставок RUSFAR CNY/RUB. Это показатели активности и стоимости фондирования, не заявочный order flow. Общедоступный ISS history probe не вернул объём валютных торгов; недоступное поле не выдумывается. [ISS и фиксации](https://www.moex.com/files/4wcf2eg0gwpgk4220krw4xtan1).

Для KASE/Halyk дата доступности — наблюдаемый день +1 календарный день, чувствительность +2. Halyk хранит дату графика как midnight Asia/Almaty: используется историческая IANA зона, включая изменение UTC offset в марте 2024. Конфликтующие значения с одинаковым timestamp исключаются целиком, сохраняются в `halyk_*_conflicts.csv`. Это EOD snapshot с консервативным лагом, а не верифицированный архив публикаций. Возраст последней доступной записи ограничен семью днями после даты доступности; backfill запрещён.

Признаки цен и ликвидности проверяются отдельно. У объёма используется нормировка на прошлую rolling median, у illiquidity — абсолютное изменение VWAP на единицу фактического объёма; цены с нулевым объёмом исключены. Не называем эти показатели исполнимым спредом, направлением заявок или причинной оценкой дефицита ликвидности.

Шесть групп × два train-окна × два лага = 24 конфигурации, по четыре annual folds. Добавлены четыре явно исследовательские комбинации с Treasury и компактным EXMO RUB. Hyperparameters HGB сохранены: depth2, 120 iterations, learning rate .05, leaf40, L2=2; early stopping выключен. Предыдущий validation год отделён и purged; OOT даты совпадают с V3. 2026 уже был просмотрен и остаётся диагностикой.

Publicly downloadable не означает unrestricted коммерческую ML-лицензию. KASE отдельно продаёт историю заявок/сделок и другие market-data продукты; эта работа использует доступные дневные результаты как исследовательский PoC, не обход платного архива. [Описание коммерческого архива](https://kase.kz/en/information/archived-trade-information). Детального historical order book и all-in quote Альфы здесь по-прежнему нет.

## Воспроизведение

Из корня AlphaTransfer, Python 3.11 с numpy/pandas/scikit-learn/pyarrow/threadpoolctl:

```sh
python research_v4/liquidity/fetch_kase.py
python research_v4/liquidity/fetch_halyk.py
python research_v4/liquidity/experiment.py
python research_v4/liquidity/run_combo.py
python research_v4/analyze_market.py
```

Исходные ответы и frontend provenance: `raw/`; URL/хэши: `kase_receipts.json`, `halyk_receipts.json`; признаки и их доступность: `feature_receipt_*`; модели/вероятности: `checkpoints/`, `predictions/`; результаты всех конфигураций: `metrics.csv`, `combo_metrics.csv`. Общий readout и парные интервалы лежат уровнем выше.
