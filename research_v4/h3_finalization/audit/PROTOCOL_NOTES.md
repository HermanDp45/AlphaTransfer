# H3 finalization: независимый протокол и контракт

Пользователь явно выбрал **TabM KZT H3**. H5 и pooled-модель не являются допустимой автоматической заменой. Проверяем только окно 120 месяцев против расширяющейся истории с 2010 года при неизменных FULL33, seed2, модели, inner epoch selection, 12 месяцах calibration и наборе политик.

История выбирается по сохранённому правилу устойчивости на annual2024/2025/2026, не по одному удачному 2026. Это ретроспективный выбор. Сравнение каждой политики с самой собой отделяет влияние истории от смены политики. Частичные выигрыши допустимы, но ухудшение отдельного года или покрытия показывается; запрещено составлять фиктивную историю из лучшей модели каждого года.

## Честная финальная калибровка

Для deployment cutoff **2026-09-05** рекомендован тот же рецепт, что в годовом сравнении: выбранное окно train заканчивается до **2025-09-05**, calibration занимает последние 12 календарных месяцев; train targets должны фактически созреть до начала calibration, calibration targets — до deployment cutoff. Последние известные зрелые метки участвуют в calibration и настройке политики, а не одновременно в обучении весов и оценке калибратора. Финальный checkpoint не имеет будущего OOT-теста: исторические метрики относятся к ежегодному рецепту, а не к этому новому fit.

Обучение весов на всех зрелых примерах с последующим Platt на их же fitted probabilities неприемлемо как честная калибровка. Альтернатива — временные cross-fitted OOT scores для калибратора и последующий refit весов на всех зрелых данных; такой калибратор переносится на другую модель и требует отдельной проверки такого же рецепта в annual folds. Без этой дополнительной проверки последний 12-месячный holdout остаётся наиболее сопоставимым вариантом.

Для ранговой политики reference последних 63 score пересчитывается тем же финальным checkpoint и калибратором. Последние даты с незрелыми исходами используются как известные feature/score строки; их метки не подмешиваются в calibration. Текущий score добавляется в reference только после вычисления его ранга. При смене model/calibration/history начинается новая версия состояния.

## Интеграция и сценарии

- Новый model contract явно содержит `target_horizon=3`, KZT scope, feature order, weights/preprocessor/calibrator hashes, выбранную политику и cutoff. State привязывается к конкретной версии этого контракта, а не только к общему названию TabM.
- Первичный NOW H3 означает отсутствие более дешёвой цены в следующих трёх сессиях. Из него не следует endpoint-rise или «окно закрывается».
- Старые `final_sprint/model/closing.pkl` и `closing_annotation.json` обучались/настраивались для прежнего H5 профиля. Их нельзя автоматически копировать как H3. Допустим NOW-only профиль с явно отсутствующей CLOSING-оценкой либо отдельно обученный и откалиброванный CLOSING_H3 со своей меткой, checkpoint и порогом.
- Для daily API календарная дата означает batch10:05 Europe/Moscow. Intraday timestamp раньше10:05 нельзя молча нормализовать и вернуть признаки10:05 как уже известные; либо daily-only вход с явным reject intraday, либо отдельная корректная фильтрация по времени.
- Проверить round-trip/binary feature serialization, order/duplicate/session-gap guards, processed cursor, initial rank reference и contact state, полное против incremental исполнение, повторную обработку даты, несовместимые state и будущее poisoning. Новые runtime predictions не должны содержать реализованные будущие исходы среди inputs.
- Source-daily факты и model verdict раздельны; отправка внешних уведомлений не происходит. Финальный фит является пакетом для интеграции/пилота, а не свидетельством фактической банковской прибыли.
