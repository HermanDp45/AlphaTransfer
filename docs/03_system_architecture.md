# Архитектура прототипа

## Граница решения

Прототип работает только с открытыми валютными рядами и синтетическим списком демонстрационных получателей. Он не подключается к CRM, пуш-провайдеру, процессингу, внутренним витринам или персональным данным. Курс ЦБ используется как публичный индикатор; на экране перевода пользователь видит отдельно рассчитанный «актуальный курс» прототипа/приложения.

## Поток данных

```text
Открытый API/выгрузка ЦБ РФ
          │
          ▼
Загрузка → проверка схемы и дат → нормализация Value / Nominal
          │                            │
          │                            └─ календарные метки публикаций
          ▼
Хранилище рядов (дата публикации, валюта, rub_per_unit, источник)
          │
          ▼
Feature builder (только данные ≤ as_of_date)
          │
          ├─ базовые индикаторы
          ├─ ML-вероятность / калибровка
          └─ объяснения и параметры для текста
          ▼
Signal scorer → конфликт-резолвер → cooldown / недельный лимит
          │
          ├─ Таблица candidates (для бэктеста)
          └─ Таблица sent_triggers (для демонстрации)
                    │
                    ├─ генератор комплаенс-текста
                    └─ deep link на прототип перевода
                                      │
                                      ▼
                           экран актуальности при открытии
```

## Контракты данных

**Входной ряд**

| Поле | Назначение |
|---|---|
| `published_at` | дата публикации / дата, когда значение стало доступно алгоритму |
| `currency` | TJS, UZS, KGS, AMD или KZT |
| `value`, `nominal` | исходное значение ЦБ и номинал |
| `rub_per_unit` | нормализованный курс; единственный вход для сопоставимых признаков |
| `source_url` | воспроизводимая ссылка на источник |

**Выход сигнального слоя**

| Поле | Назначение |
|---|---|
| `as_of_date` | дата среза; критична для аудита отсутствия look-ahead |
| `corridor` | например `RUB→TJS` |
| `indicator`, `direction`, `scenario` | причина, смысл движения и сценарий текста |
| `score`, `strength`, `speed` | управляемое ранжирование и сравнение быстрых/медленных сигналов |
| `evidence` | параметры факта: окно, процентиль, серия, изменение |
| `status` | `candidate`, `suppressed_cooldown`, `suppressed_cap`, `sent` |
| `copy_template_id`, `copy_params` | воспроизводимый фактический текст |

## Ключевые инварианты

1. `alphatransfer signal --as-of T` должен дать тот же результат независимо от наличия строк после T в файле.
2. Нормализация делается до любых расчётов и один раз в ingestion-слое.
3. Сырые кандидаты не равны коммуникациям: лимиты и cooldown фиксируются явно в `status`.
4. Все веса и пороги версионируются по коридору и walk-forward-фолду.
5. Любой отправленный пуш должен раскрывать основание через `evidence` и шаблон из библиотеки.

## Минимальный оркестратор в стиле n8n

Приложенный n8n-файл структурно показывает цепочку специализированных узлов (исследование, сегменты, интервью, гипотезы, RICE, Lean Canvas и финальный продуктовый узел), но повреждён синтаксически в конфигурации HTTP-узла. Для этого кейса безопаснее не исполнять его, а воспроизвести паттерн специализированными шагами:

1. `LoadRates` — скачать/прочитать открытую выгрузку.
2. `NormalizeAndValidate` — норминалы, пропуски, дата доступности.
3. `GenerateSignalsAsOf` — детерминированные признаки и кандидаты.
4. `BacktestWalkForward` — исключительно offline-оценка будущих исходов.
5. `RankAndThrottle` — единый поток разрешённых триггеров.
6. `RenderCopy` — только по разрешённым шаблонам и фактическим параметрам.
7. `DemoUI` — показать пуш, глубокую ссылку и сценарий устаревшего момента.

Каждый шаг принимает и возвращает структурированные записи, а не свободный текст модели. Генеративные модели могут помогать с макетом и обзором практик в star-части, но не входят в контур, который принимает решение об отправке.
